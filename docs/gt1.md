# GoatTracker V1.x packed tunes

GoatTracker V1.x saved a tune by copying one of its playroutines, relocating it
and appending the song tables (`relocator()` in the editor's `goattrk.c`). This
library recognizes the playroutine, decompiles the tables into a `Gt1Song` and
plays it with `Gt1Player`, which runs a `pysidtracker.playspec` spec of that
playroutine on the tune's own memory. Three
playroutine designs are supported: the V1.5x standard playroutine, the V1.3–V1.4f
playroutines it was rewritten from, and the musicroutine 11.x family (the V1.25
musicroutines 11.1–11.5 and the V0.96–V1.22 standard playroutines they grew
from).

## Recognition

No playroutine code is in the package. `src/pygoattracker/_gt1_builds.py` holds
facts about each build, generated by `scripts/gt1_refs.py` (`gt1.analyse`) from
the playroutines assembled at `$1000`: the family, label offsets, the author
range, the length, each relocated operand's offset and assembled word, the
parameter slots, the self-modified operands, the zero-page temporaries and two
weighted sums of the bytes the packer keeps.

The recognizer replays the packer's relocation walk (skip the author block, stop
at the first `$00`/`$01` opcode, relocate every absolute operand outside `$D4xx`,
fill the four `$FF` parameter slots); what the packer or the running tune may
change (relocated operands, the parameter slots, the author name, the operands
the routine modifies itself and its zero-page temporaries) is wild. One FFT
correlation of memory with each build's weights over its fixed bytes gives every
address whose sums match; a candidate is accepted only if every code operand
moved by the same offset and every operand on the same virtual table page
(`$40xx`..`$47xx` for V1.4x and V1.5x, `$40xx`..`$90xx` for 11.x) names the same
table base. Builds whose fixed bytes agree are told apart by a digest of their
frequency tables.

A decompiled `Gt1Song` keeps its tune's playroutine (`gt1.extract_code`) for
`pack`/`to_sid`. A song made from scratch or an editor song needs its build's code
registered first (`gt1.register_code(name, code)`, checked against the facts);
the tests register each build assembled from the fixture-cached sources on
[Cadaver's tools page](https://cadaver.github.io/tools.html) or extracted from a
pinned HVSC tune (`tests/_gt1_code.py`).

## Decompile

`decompile_gt1(data, subtune)` reads the table bases from the matched operands
(the pre-V1.1 packers point the song table operands one song, three bytes,
before the table)
and checks that the tables tile the memory after the player: instruments (8
bytes each), the wave and note columns, the song table (low then high bytes),
the pattern table, the filter table (V1.4x and V1.5x), the orderlists and the packed
patterns. Packers placed the orderlists before or after the pattern table, so
the order found is kept in `Gt1Song.segments`. The `Gt1Song` keeps the player's state as saved in the image (operands it
modifies, zero-page operands, channel variables and frequency tables), so
`Gt1Song.pack()` reproduces the image bytes exactly. A last pattern cut short
by the end of the file keeps only the loaded bytes.

A header init that is neither the packed entry (the jump table, or the packer's
init stub before a playroutine without one) nor the packer's multispeed CIA
speed code (an HVSC init stub) is run in the 6502 emulator first, and the song
is decompiled from memory after init.

## Playback

`Gt1Player` is a `pysidtracker.playspec.SpecPlayer`: the tune's own init runs in
the 6502 emulator, then each play call runs the family's spec
(`src/pygoattracker/specs/gt1_15.play`, `gt1_14.play` or `gt1_11.play`) on that
memory. `pygoattracker.gt1spec.binding` binds a spec's `layout` from the relocated
reference `find_player` matches: the playroutine labels (channel variables), the
relocated table bases, the self-modified operands (`Reference.smc` in code order,
including the jump-table dispatch operands), the packer's parameters and the
zero-page temporaries as the tune's code addresses them. Release differences
within a family are static `flag`s of the layout. The spec writes every byte the
6502 writes outside the stack page, so memory after each call equals the tune's
own run; reads of pattern or orderlist data that alias the stack page are the one
thing it cannot follow. One `render_grid` row is one play call; multispeed timing
comes from the tune's CIA programming (`pysidtracker.cadence.playroutine_cadence`),
never from header flags. `Gt1Player.loops` counts the loop and end marks the
sequencer reads in each channel's orderlist. With `validate=True` each pattern and
orderlist the spec opens is parsed under the `gt1streams.lark` rule it names. A playroutine
without the V1.22 `clc` adds the carry play is entered with to the cutoff
slide; sidplayfp's PSID driver calls play from its interrupt handler, whose
`rti` restores the flags its idle loop had after init, so that carry is the one
init returned with (clear for the packed entry points).

`tests/test_gt1.py` packs synthetic songs that use every command, table feature
and orderlist command with each playroutine (the V1.4x multispeed one with a
hard restart length set) (and a sound effect for 11.2/11.4)
and checks `Gt1Player` against the packed 6502 playroutine itself, entered as
the PSID driver enters it, frame for frame. `tests/test_gt1_playspec.py` checks
the registers and the 64 KiB outside the stack page and I/O against the tune's own
6502 after every call, on synthetic songs and (marked `oracle`) over the whole song
of every GT1 oracle tune, and proves the V1.53 row reader (`chan[0].getnewnotes`,
from the pattern pointer load to the next channel's step) equal to the 6502 code
for all initial memory with `pysidtracker.playspec.tv.validate`.
`scripts/spec_memcheck.py` runs the same memory check over an HVSC `find` CSV
(`scripts/memcheck_report.py` tallies it per playroutine) and
`scripts/gt1_disasm.py` lists a reference playroutine with its labels.

## V1.x editor songs

Every V1.x editor saved `GTS!` songs: the V0.9x editor, the V1.25 editor
(musicroutines 11.x), and the V1.4b–V1.53 editors (standard playroutine). They
share the body — name/author/copyright, orderlists, 31 instruments with inline
`(wave, note)` wavetables, and patterns in editor rows — and differ in two
places: the V0.9x orderlists carry the endmark with no restart byte and their
wavetables end in a `$00` waveform row (at most 64 rows), while the V1.4b–V1.53
editors append a 256-byte filtertable, 64 four-byte steps the playroutine
glides through: control, mode/volume (a slide: its time), cutoff (a slide: its
speed) and the next step; step 0 starts the glide. The layout is detected from the first wavetable's terminator (which
the orderlists alone cannot decide, since `$FE` endmarks are byte-identical),
and by the filtertable tail.

`parse_gts1(data, player=None)` parses any layout into a `Gt1Song` whose
`sng` field carries the raw 3×32 header and the detected layout (`player`
pinned by the layout's default `11.3` / `1.53`; V0.9x songs are native-only),
`write_gts1(song)` reproduces the file byte for byte, and `relocate(song)`
ports the editor's F9 relocator (`relocator()` in the respective `goattrk.c`):

* V1.25: referenced patterns are packed into the musicroutine row form
  (sticky instruments, tempo data−1, timing marks cleared for 11.1/11.2,
  vibrato nybbles swapped, row and rest compression), instruments and
  wavetables are trimmed to what plays, and the player's author block
  (11.3–11.5) is stamped. An instrument's +6 byte stays a direct filter
  freq/type value, and the oldest saves' `$FE` endmark normalizes to the
  `$FF` restart endmark.
* V1.4b–V1.53: patterns gain the standard row form (tempo data−1 for
  data ≥ 3, vibrato nybbles swapped, set-filter data × 4, arpeggio high bit
  toggled), instruments the standard field form (pulse nibble split, pulse
  bounds shifted down a nibble, filter × 4), and the filtertable is trimmed
  to the highest referenced step plus one, its later steps' fourth byte × 4
  and step 0 decremented one with wrap. Orderlist entries at `$D0` and above
  are the playroutine's commands and pass through unreferenced; a subtune
  with a dead channel — and, if all are dead, the whole file — is discarded,
  and the deduped wavetable may not exceed 512 bytes.

`pack()`, `Gt1Player` and `to_sid` all operate on that packed form,
byte-identical to what the editor itself wrote: `tests/test_gt1sng.py` checks
all six `goatold.zip` V1.25 songs and all six `goattrk.zip` V1.4b–V1.53 songs
against that rule and the 6502 playroutine itself, with the GoatClassical and
Dojo examples matched byte for byte to their GVSC releases.

The V0.9x body is native-only: its playroutine is not transcribed, so
`relocate` (and so `pack`, `to_sid`, and `Gt1Player`) raise a clear
`SngValidationError`, while `parse_gts1`/`write_gts1` round-trip the
`goattrk093.zip` example songs byte for byte. `Gt1Song.to_gt2()` (and
`read_sng(..., convert=True)`) keeps GoatTracker 2.76's lossy GT2 import of
the V1.4b–V1.53 layout; the V0.9x and V1.25 bodies are native only.
